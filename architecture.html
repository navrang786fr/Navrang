03 Core Subsystem Details

Modular Architecture
📱

Customer PWA Shell

order.html & order-app.js
Flagship digital menu loaded instantaneously via QR code scans placed on dining tables.
  • Bilingual Translation Engine: Instant real-time toggle between English and Telugu (`తెలుగు`) with complete string dictionary.
  • Smart Search & Multi-Filters: Instant indexing across dish titles, Telugu script, and ingredients with Veg/Non-Veg pills.
  • Biryani Catcher Game: 60 FPS HTML5 Canvas mini-game with retro particle physics while waiting for food.
  • Split Bill Utility: Native bill division for guest groups with clipboard copy and downloadable receipt screenshots.
  • Social Channels: Direct integration with YouTube Channel & Instagram 5% OFF discount campaign.
🖥️

On-Premise POS Server

server.py & pos-orders.json
Local multi-threaded Python server coordinating table orders and cashier billing over LAN.
  • Zero Cloud Dependence: Restaurant operations continue smoothly even during complete broadband outages.
  • Thread-Safe Storage: Atomic file swapping on `pos-orders.json` prevents race conditions during dinner rush.
  • Waiter Handheld Mode: Tables, item add/remove, kitchen ticket dispatch with sub-millisecond local latency.
  • Counter POS Mode: Bill settlement, tender selection (Cash/UPI/Card), and thermal receipt printing.
  • Daily Collections Audit: Automated end-of-day revenue audit and settlement reports.
⚡

Cloud Serverless Microservices

ratings-api/api/*.js
Node.js serverless microservices hosted on Vercel handling customer reviews, telemetry, and catalog CRUD.
  • Git-as-a-Database: Public/Private GitHub repos as relational state storage with version history.
  • Optimistic Concurrency: SHA-validated PUT commits with retry loops on concurrent 409 conflicts.
  • Sliding-Window Throttling: IP rate limiting to prevent spam and review manipulation.
  • Automated Backups: Daily Vercel Cron worker snapshots 7-day activity logs.
  • Stateless JWT Auth: HMAC-SHA256 tokens for admin and management portals.

04 Architectural Decisions (ADRs)

Key Trade-offs

Engineering decisions that define the platform's reliability, simplicity, and zero operating overhead:

ADR-001 • DATA TIER

Git-as-a-Database with Optimistic Concurrency

Instead of provisioning managed cloud SQL/NoSQL databases (RDS, MongoDB, Supabase) with recurring monthly bills, data is persisted as version-controlled JSON files committed via the GitHub Contents API.
Trade-off: Write latency is ~400ms (acceptable for reviews, game plays, and catalog edits), while read operations are globally cached on GitHub CDN for sub-10ms response times.
ADR-002 • RESILIENCE

Local-First LAN POS vs Cloud-Only Ordering

Commercial restaurants cannot afford POS downtime when local broadband drops. The floor POS runs on an on-premise Python 3 server on the dining room's local Wi-Fi router.
Trade-off: Requires a local PC/laptop running `server.py`, but guarantees 100% dining room ordering and billing uptime regardless of telecom stability.
ADR-003 • AUDIO SYSTEM

Procedural Web Audio Synthesis vs Audio Assets

The Biryani Catcher mini-game synthesizes audio chimes, bells, and collision bursts procedurally using the Web Audio API (`AudioContext`, `OscillatorNode`, `GainNode`) rather than loading MP3 files.
Trade-off: Requires programmatic frequency curves, but eliminates 100% of audio bandwidth, avoiding 404 file errors and audio decode lag on cellular connections.
ADR-004 • FRONTEND STACK

Vanilla Web Platform vs Single-Page Frameworks

The entire customer application is implemented with semantic HTML5, CSS Custom Properties, and Vanilla ES6+ without React, Vue, or Webpack bundle toolchains.
Trade-off: Manual DOM updates, but achieves sub-100ms First Contentful Paint (FCP), instant QR code menu loading on budget Android devices, and zero build tool maintenance.

08 Reliability & Security Pillars

Production Verified

1. Survives Total Internet Outages

The floor POS system runs on an on-premise local server (`server.py`). Even if the restaurant's broadband connection is completely severed, waiters can still place table orders, the kitchen receives KOTs, and the counter can print receipts and log cash payments seamlessly over the local Wi-Fi router.

2. Zero Plaintext Credential Exposure

Administrative tokens, JWT secrets, and fine-grained GitHub PATs are injected securely as serverless runtime environment variables (`JWT_SECRET`, `ADMIN_GITHUB_TOKEN`). Public repositories contain zero database passwords or private API keys.

3. Customer Privacy by Design (SAIF Framework)

Sensitive diagnostic data like customer IP addresses, device user agents, and geolocation are segregated into the private `admin-db` repository. Public assets served to browsers (`ratings.json`, `menu-data.js`, `game-stats.json`) strictly contain sanitized business data.

4. Zero CDN Stale Cache Headaches

Whenever an administrator changes a dish price or adds an item, the script loader appends a fresh timestamp hash (`menu-data.js?v=Date.now()`), completely bypassing aggressive mobile browser caches without requiring manual cache clearing by dining customers.
